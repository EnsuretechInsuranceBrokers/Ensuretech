## 2. Member-identifying fields (proven from the endorsement pipeline)

Endorsement sheets are keyed by these field names (DB `feild_name`; the header labels are DB-driven, see 3):
- `employee_code` - trimmed, regex `/^[a-zA-Z0-9 -\/]*$/`; NewUpdateEndorsedMemberJob.php:1051 (trim), :1256-1257 (pattern), :1260-1275.
- `relationship_with_employee` - must equal a `RelationMaster.name` AND be one of the policy's `ageDetails->relations->name`; NewUpdateEndorsedMemberJob.php:1066, :1244-1253. Known names: 'Self', 'Spouse', 'Son', 'Daughter', 'Father', 'Mother', 'Father-in-law', 'Mother-in-law' (TestController.php:7625). Relation ids: Self = 1 (NewUpdateEndorsedMemberJob.php:1268-1275 uses `relation_id == 1`), Spouse = 2 (:345).
- **`endrosement_number`** (note the legacy spelling) - the real per-member key for UPDATE. Looked up as `EmployeeMembers.endorsement_id` (NewUpdateEndorsedMemberJob.php:1067-1068, :155). Required; missing gives "Endorsement number is required", unknown gives "Invalid endorsement number" (:1070-1077). If a relation is given it must match that member's relation, else "Invalid endorsement number for this member" (:1078-1082).
- Insurer/TPA ids: `tpa_member_id` exists on members (EndrosementEnrollementController.php:3873). **'Insurer Removal Id' and any insurer-id column: no occurrence of the string in any uploaded PHP file -> UNKNOWN.**

## 3. Headers of ADD / REMOVE / UPDATE sheets

Header text comes from table `DefaultEndrosementFormatFeildsMapping` columns `default_feild_name` (label), `feild_name` (field key), `sequence`, `status`, `is_mandatory`, `feild_validation`, `tpa_id`, filtered by `default_endrosement_format_id` (EndrosementEnrollementController.php:1484, :8484; NewUpdateEndorsedMemberJob.php:1852; helper.php:7287-7295). Rows are seeded by `DefaultEndrosementFormatFeildsMappingSeeder` (admin_api.php:2277), whose content is **not uploaded -> exact label strings UNKNOWN**.
Fields in `getNewTataFields()` are excluded from the default sheet (helper.php:9068-9093+; partial list seen: member_middle_name, marital_status, parent_id, category, passport_no, ... dha_member_id, birth_certificate_id; full list not read past :9093).
A policy may use a custom template instead (`CustomFormatController::checkCustomPolicyFormat`, labels from `templateFields.label`): NewUpdateEndorsedMemberJob.php:1787, :1800; EndrosementEnrollementController.php:1475-1481.

Format ids (`default_endrosement_format_id` / `typeId`): 1 = ADD, 2 = REMOVE, 3 = UPDATE/correction (NewUpdateEndorsedMemberJob.php:1763-1777; EndrosementEnrollementController.php:8454-8460; helper.php:7272-7295 maps upload types 3/4/5 to format ids 1/2/3). Caution: `ExcelErrorReports.document_type_id` uses 3 = add, 4 = remove, 5 = update (EndrosementEnrollementController.php:1452-1460; TestController.php:2514 uses `document_type_id = 4` for remove) while `typeId`/format id uses 1/2/3. Do not mix them.

Error-report sheets append `Status` and `Reason` columns after the labels (NewUpdateEndorsedMemberJob.php:1815-1826; success texts 'Member added successfully.', 'Member Deleted Successfully.', 'Member Corrected Successfully.', failure 'Failed to add.' / 'Failed to Delete.' / 'Failed to Correct.', :1763-1777).

## 4. Value and date formats (proven)
- Dates: sheet parser `validDate()` accepts Excel serial, `d/m/Y`, `d-m-Y`, `Y-m-d`, `Y/m/d`, `d.m.Y`, then Carbon::parse; output normalised to **`d-m-Y`** (helper.php:3229-3273). Dumps built by code use `d-m-Y` (TestController.php:5551-5570, :11124-ish).
- Gender: validator accepts 'male','Male','female','Female','Other','other' (NewUpdateEndorsedMemberJob.php:1344-1350); generated rows use capitalised 'Male'/'Female' (TestController.php:5382-5391 dictionary).
- Relation: `RelationMaster.name`, e.g. 'Self','Spouse','Son','Daughter','Father','Mother' (TestController.php:7625).
- Names: `/^[A-Z. ]*$/i` (NewUpdateEndorsedMemberJob.php:1255). Mobile: exactly 10 digits (:1352-1366). Pincode: 6 digits (message :1100-1104). Yes/No flags: 'Yes'/'No' (e.g. should_verify_email 'No', TestController.php:5586).
